# 風力発電量シミュレーター 仕様書

## 1. 文書情報

| 項目 | 内容 |
|---|---|
| システム名 | WIND / PULSE |
| 目的 | 現在地の風況から風力発電量を概算する |
| 対象 | スマートフォン、PC のブラウザ利用者 |
| 公開先 | Vercel |
| データ提供元 | Open-Meteo Forecast API |
| 位置情報 | ブラウザ Geolocation API |

## 2. 概要

利用者がブラウザの位置情報利用を許可すると、現在地の緯度・経度を取得する。取得した座標を Open-Meteo に送信し、現在の風速と当日 24 時間の風速予測を取得する。風速、ローター直径、空気密度、パワー係数から理論上の発電出力を計算し、瞬間出力、kW、1 時間発電量、24 時間予測として表示する。

本アプリの発電量は気象データと簡易モデルに基づく推定値であり、系統連系、機器効率、乱流、風向、地形、保守状態、実機の出力曲線などは考慮しない。

## 3. 機能要件

### 3.1 現在地取得

- Geolocation API の `getCurrentPosition` を使用する。
- 緯度、経度を取得して画面に表示する。
- 高精度取得を要求する。
- タイムアウトは 10 秒、キャッシュ利用期限は 5 分とする。
- 権限拒否、取得失敗、API 非対応を利用者向けメッセージに変換する。
- 「現在地を更新」操作で再取得できる。

### 3.2 気象データ取得

- 現在地取得後に Open-Meteo Forecast API を呼び出す。
- 現在風速 `wind_speed_10m` を取得する。
- 24 時間分の毎時風速予測を取得する。
- タイムゾーンは Open-Meteo の `auto` とし、地点の現地時刻で扱う。
- HTTP エラー、通信エラー、レスポンス項目不足を画面に表示する。
- 位置情報が未取得の場合は API を呼び出さない。
- 新しい位置情報が取得された場合、古い通信結果が画面を上書きしないよう通信をキャンセルする。

### 3.3 発電量計算

計算式は次のとおりとする。

$$
P = \frac{1}{2} \rho A C_p V^3
$$

受風面積は次で求める。

$$
A = \pi \left(\frac{D}{2}\right)^2
$$

| 記号 | 意味 | 初期値・条件 |
|---|---|---|
| `P` | 発電出力 | W |
| `rho` | 空気密度 | 1.225 kg/m³ |
| `A` | 受風面積 | `pi * (D / 2)^2` |
| `Cp` | パワー係数 | 0.35 |
| `V` | 風速 | m/s |
| `D` | ローター直径 | 3 m |

実機の運転範囲を簡易的に反映し、風速が 3 m/s 未満または 25 m/s 超の場合は発電出力を 0 W とする。計算結果は W、kW、1 時間分 kWh、24 時間分 kWh に変換する。

### 3.4 表示

- 現在地カード: 緯度、経度、更新操作
- 風況カード: 現在風速、運転状態、カットイン・カットアウト条件
- 発電量カード: W、kW、1 時間発電量、24 時間予測
- 地図: OpenStreetMap タイル、現在地ピン
- グラフ: 今後 24 時間の推定発電量
- 設定: ローター直径 1 m から 10 m、初期値 3 m
- テーマ: ライトモード、ダークモード
- PWA: manifest、アイコン、service worker によるホーム画面追加対応

## 4. 非機能要件

- スマートフォンと PC の画面幅に対応する。
- 位置情報は明示的なブラウザ許可を必要とする。
- Open-Meteo の API キーをクライアントへ埋め込まない。
- API 取得中、データなし、エラー状態を区別して表示する。
- Vercel の標準 Next.js ビルドでデプロイできる。
- HTTPS 配下で Geolocation API と PWA を利用する。

## 5. 制約・前提

- Open-Meteo の風速は高度 10 m の `wind_speed_10m` を使用する。
- 風車固有の出力曲線がないため、物理式による概算を採用する。
- 24 時間予測は各時刻の風速を現在と同じローター条件で計算する。
- 24 時間予測は将来の風速を積算した厳密な発電保証値ではない。
- OpenStreetMap タイルの利用規約と帰属表示に従う。
