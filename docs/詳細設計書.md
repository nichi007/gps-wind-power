# 風力発電量シミュレーター 詳細設計書

## 1. API 連携方針

### 1.1 採用 API

Open-Meteo Forecast API の次のエンドポイントを使用する。

```text
GET https://api.open-meteo.com/v1/forecast
```

採用理由は以下のとおりである。

- API キー不要で、Vercel の公開クライアントから安全に呼び出せる。
- 現在値と時間別予測を一つのエンドポイントで取得できる。
- `wind_speed_10m` が風力発電の概算に直接利用できる。
- 緯度・経度による地点指定に対応している。
- `timezone=auto` により利用地点の時間軸でグラフを表示できる。
- JSON 形式で扱いやすく、依存ライブラリなしの `fetch` で連携できる。
- 気象データの利用条件と API 仕様が公開されており、試作から小規模公開まで導入が軽い。

今回のアプリは API キーを必要とせず、個人の現在地を保存しない。そのため API プロキシを先に設けるより、ブラウザから直接取得するほうが構成が小さく、Vercel 上の運用コストと障害点を減らせる。ただし、リクエスト制御、監査ログ、キャッシュ、認証が必要な商用運用では Next.js の Route Handler をプロキシとして追加する。

### 1.2 リクエスト仕様

現在の実装は `hooks/useWindData.ts` から次のクエリを生成する。

```text
https://api.open-meteo.com/v1/forecast?
  latitude={latitude}&
  longitude={longitude}&
  current=wind_speed_10m&
  hourly=wind_speed_10m&
  forecast_days=1&
  timezone=auto
```

| パラメータ | 値 | 必須 | 意味 |
|---|---|---:|---|
| `latitude` | Geolocation の緯度 | Yes | 取得地点の緯度 |
| `longitude` | Geolocation の経度 | Yes | 取得地点の経度 |
| `current` | `wind_speed_10m` | Yes | 現在の高度 10 m 風速 |
| `hourly` | `wind_speed_10m` | Yes | 毎時の高度 10 m 風速予測 |
| `forecast_days` | `1` | Yes | 当日を含む 1 日分 |
| `timezone` | `auto` | Yes | 地点のタイムゾーンで返却 |

クエリ文字列は文字列連結ではなく `URLSearchParams` で生成する。これにより座標の符号、小数点、URL エンコードを一貫して処理できる。

### 1.3 位置情報 API 仕様

ブラウザの `navigator.geolocation.getCurrentPosition` を使用する。

```text
enableHighAccuracy: true
 timeout: 10000 ms
maximumAge: 300000 ms
```

`enableHighAccuracy` は現在地に近い風況を得るために有効化する。一方で端末の電力消費が増えるため、常時監視の `watchPosition` ではなく、初回と利用者操作時の単発取得とする。`maximumAge` は 5 分とし、頻繁な位置取得を避ける。

成功時に次の内部型へ正規化する。

```ts
export type Coordinates = {
  latitude: number;
  longitude: number;
};
```

### 1.4 レスポンス仕様

Open-Meteo から次の形の JSON が返ることを期待する。

```json
{
  "current": {
    "wind_speed_10m": 6.4
  },
  "hourly": {
    "time": ["2026-08-27T10:00", "2026-08-27T11:00"],
    "wind_speed_10m": [6.4, 7.1]
  }
}
```

実装では次を検証する。

1. HTTP ステータスが成功であること。
2. `current.wind_speed_10m` が number であること。
3. `hourly.wind_speed_10m` が配列であること。
4. `hourly.time` と風速配列の同じインデックスを時系列として扱えること。
5. 表示対象を先頭 24 件に制限すること。

検証後は外部 API の構造を画面へ漏らさず、次の内部型へ変換する。

```ts
export type WindPoint = {
  time: string;
  speed: number;
};

export type WindData = {
  currentSpeed: number;
  hourly: WindPoint[];
};
```

### 1.5 通信ライフサイクル

`coordinates` が変化するたびに `useEffect` 内で通信を開始する。effect の終了時に `AbortController.abort()` を呼び出し、古い座標のレスポンスが新しい座標の画面状態を上書きすることを防ぐ。

```text
coordinates null
  -> API 呼び出しなし
coordinates set
  -> loading=true, error=null
  -> fetch 開始
  -> 成功: data 設定, loading=false
  -> HTTP/JSON/通信失敗: error 設定, loading=false
  -> AbortError: エラー表示せず終了
```

### 1.6 エラー分類と画面表示

| 発生箇所 | 判定 | 画面への表示 |
|---|---|---|
| Geolocation API | API 非対応 | このブラウザは位置情報に対応していません |
| Geolocation API | `PERMISSION_DENIED` | 位置情報の利用許可を案内 |
| Geolocation API | timeout / position unavailable | 現在地を取得できない旨と再試行 |
| `fetch` | `response.ok` が false | 気象データ取得失敗 |
| JSON 検証 | 必須項目不足 | 気象データ取得失敗 |
| `fetch` | AbortError 以外の例外 | 通信状況の確認を案内 |
| 表示 | 座標または気象データが null | プレースホルダーを表示 |

利用者には内部例外、URL、スタックトレースを表示しない。詳細な監視が必要になった場合はサーバー側プロキシとログ基盤を追加する。

## 2. 計算詳細

### 2.1 現在値

`calculateWindPower(windSpeed, rotorDiameter, airDensity, cp)` は副作用を持たない。入力値から受風面積を求め、運転範囲外なら 0、範囲内なら物理式で出力を求める。

```ts
const sweptArea = Math.PI * (rotorDiameter / 2) ** 2;
const watts = windSpeed < 3 || windSpeed > 25
  ? 0
  : 0.5 * airDensity * sweptArea * cp * windSpeed ** 3;
```

返却値は次のとおり。

```ts
{
  watts: number,
  kilowatts: number,
  hourlyKWh: number,
  dailyKWh: number
}
```

`hourlyKWh` は一定風速が 1 時間続く仮定で `watts / 1000`、`dailyKWh` は同条件が 24 時間続く仮定で `hourlyKWh * 24` とする。

### 2.2 24 時間予測

各時刻の風速を同じローター直径、空気密度、パワー係数で計算する。グラフの単位は kW とし、カットイン・カットアウトの範囲外は 0 とする。これは時間ごとの瞬間出力を描画するもので、時間帯ごとの電力量を厳密に積分するものではない。

## 3. 地図連携詳細

`react-leaflet` の `MapContainer` と `TileLayer` を使い、OpenStreetMap のタイルを表示する。Leaflet はブラウザ依存処理を含むため、`page.tsx` から `dynamic(..., { ssr: false })` で遅延読み込みする。

- 地図中心: 現在地の緯度・経度
- ズーム: 11
- マーカー: 現在地
- タイル URL: `https://{s}.tile.openstreetmap.org/{z}/{x}/{y}.png`
- 帰属表示: OpenStreetMap contributors を表示

## 4. グラフ連携詳細

`react-chartjs-2` を利用し、Chart.js の `CategoryScale`、`LinearScale`、`PointElement`、`LineElement`、`Tooltip`、`Filler` を登録する。グラフは SSR を無効化したクライアントコンポーネントとして描画し、風速配列を kW 配列へ変換する。

## 5. PWA 詳細

- `public/manifest.webmanifest` でアプリ名、起動 URL、standalone 表示、テーマ色を定義する。
- `public/icon.svg` をアプリアイコンとして使用する。
- `public/sw.js` を初回表示時に登録する。
- ルート、manifest、アイコンをキャッシュし、同一オリジンの GET はキャッシュ優先で応答する。
- Geolocation と PWA は HTTPS 配下で利用する。

## 6. 将来の改善方針

- API レスポンスの実行時スキーマ検証に Zod 等を導入する。
- Open-Meteo のレスポンスを Next.js Route Handler で代理し、短時間キャッシュとレート制御を追加する。
- 風車ごとの実測出力曲線、発電効率、稼働率、風向を入力できるようにする。
- 現在の 24 時間予測を時間積分し、発電量と瞬間出力を別系列で表示する。
- OpenStreetMap タイルの利用量が増えた場合は、利用規約に適合したタイルプロバイダーを検討する。
- 単体テストでカットイン、カットアウト、面積、単位変換を検証する。
